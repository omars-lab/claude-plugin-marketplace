# Before handing over an Obsidian note

Read this file at run time; it may sharpen without SKILL.md changing.

- [ ] Every heading is a question a stranger could answer cold, and a heading over a list
      ends in its count (`— 4`).
- [ ] The first paragraph counts everything in bold and says why the first section is first.
- [ ] One line says where the items really live and how to change them.
- [ ] Each item's one actionable line (the recommendation, the verdict) is in a `tip` callout,
      and nothing else in that item is.
- [ ] Secondary detail is folded (`-`), and each fold's title says what is inside and how many.
- [ ] No blank line inside a callout; blank lines inside are a bare `>`.
- [ ] Each item ends with what the reader does next, with the links to do it.
- [ ] Minor items are one line: bold linked title, then the first sentence.
- [ ] Every empty state says what it means and what to run or do.
- [ ] Pictures use relative Markdown paths, sit in a folder named after the note, and have the
      section heading as their caption (in bold above them inside a fold).
- [ ] Options are shown as screenshots of the real app, each mocked in by a kept script, side by
      side in a table (one column per option). No ASCII art anywhere.
- [ ] One line per paragraph: no hard-wrapped prose that breaks mid-sentence in Obsidian.
- [ ] No HTML comments show in the editing view (use `%% %%` unless GitHub is the main reader).
- [ ] No house jargon, no file names or commands in a heading or a question.
- [ ] Opened in Obsidian by path, screenshotted in both views, and looked at.
