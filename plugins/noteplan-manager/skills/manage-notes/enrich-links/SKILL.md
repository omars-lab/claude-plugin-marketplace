# Enrich Links

You are a link enrichment assistant for NotePlan notes. When invoked, you find bare URLs in plan/list files and replace them with descriptive markdown links whose text captures the core concept and question addressed — not just the page title.

## What This Skill Does

Replaces `https://example.com/page` with `[Why X matters for Y use case](https://example.com/page)`.

The link text is a **1-sentence summary** generated by a haiku sub-agent — not the raw page title. The summary should be:
- Max 12 words
- No trailing punctuation
- Focuses on: what concept the content teaches, what question it answers
- Does NOT just restate the page title

## Phase 1: Identify Files and Bare URLs

Accept input as:
- A specific file path (from hook feedback: "unenriched links found in X.md")
- A directory to scan (e.g., a Notes/ subdirectory)

Read the file using the Read tool. Find bare URLs using this pattern:
- URL appears as `https://...` or `http://...` NOT preceded by `](` (i.e., not already in `[text](url)` format)
- Skip URLs matching these patterns (no useful/stable title):
  - Private IPs: `192.168.`, `10.`, `172.16-31.`
  - Local hosts: `.local`, `.attlocal.net`, `localhost`
  - OAuth/auth callbacks: URL contains `?code=`, `?state=`, `?auth_callback=`
  - Search queries: `google.com/search`, `bing.com/search`
  - Very long URLs (>300 chars — session tokens / deep-linked state)
  - ServiceNow, SharePoint, Okta domains

---

## Phase 2: Fetch Metadata for Each URL

For each enrichable bare URL, run:

```bash
noteplan-sweep fetch-metadata "<url>"
```

This outputs YAML with `title:` and `description:` fields. Capture both.

If `fetch-metadata` fails (network error, timeout), skip that URL and log a warning.

---

## Phase 3: Generate Summaries via Haiku Sub-Agent

For each URL with fetched metadata, spawn a **haiku sub-agent** to generate the link text:

```javascript
Agent({
  subagent_type: "general-purpose",
  model: "haiku",
  prompt: `You write concise markdown link titles for personal notes.

URL: ${url}
Page title: ${title}
Description: ${description}

Write ONE sentence (max 12 words, no trailing punctuation) that captures:
1. The core concept or technique explained
2. The question or problem it addresses

Rules:
- Do NOT just restate the page title
- Do NOT start with "How to" unless it's a step-by-step tutorial
- Output ONLY the sentence — no quotes, no explanation, no prefix

Example inputs/outputs:
  Title: "Home Assistant OS Network Configuration"
  → "Configuring HA OS networking for remote and Tailscale access"

  Title: "Understanding OKRs"
  → "OKRs as a goal-setting framework linking team output to org strategy"
`
})
```

Collect the haiku response as the link text for that URL.

**Batch when possible**: if there are 5+ URLs, include them all in one haiku sub-agent call (list them in the prompt) so you get all summaries in a single round-trip.

---

## Phase 4: Write Enriched Links

For each URL, construct the markdown link: `[${summary}](${url})`

Use the Edit tool to replace each bare URL in the file. Be precise — only replace the bare URL text, not URLs already inside `[text](url)` format.

Verify after editing: the file should contain no bare `https://...` URLs that were in your enrichment list.

---

## Phase 5: Commit

```bash
cd "$NOTEPLAN_ROOT"
git add <file>
git commit -m "chore(links): enrich bare URLs in <filename> with haiku summaries"
git push
```

## Search Engine URLs — Auto-Format from Query Param

Search engine query URLs (`google.com/search?q=...`, `bing.com/search?q=...`, `duckduckgo.com/?q=...`) do NOT need Haiku summarization or a network call. Extract the `q=` parameter and format directly:

```
https://www.google.com/search?q=ha+cli+install+addon+nginx&pws=0
→ [Google: ha cli install addon nginx](url)

https://www.bing.com/search?q=what+is+a+OKR
→ [Bing: what is a OKR](url)
```

Use `urllib.parse.parse_qs` + `unquote_plus` to decode the query parameter. No sub-agent needed.

## Skip List Reference

URLs to skip silently (no warning needed):

```python
# Private IPs
r'https?://(?:192\.168\.|10\.|172\.(?:1[6-9]|2\d|3[01])\.)'

# Local hostnames
r'https?://[^/\s]*(?:localhost|\.local(?:[:/]|$)|attlocal\.net)'

# OAuth / auth callbacks
r'[?&](?:code|state|auth_callback|access_token|id_token)='

# Image / binary file extensions (nothing to title-enrich)
r'\.(jpe?g|png|gif|webp|svg|ico|bmp|tiff?|mp4|mov|pdf|zip)(\?|$)'

# UUID path segments (order IDs, download tokens — session-specific)
r'[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}'

# Internal tools (require --use-chrome in CLI, skip in skill context)
r'https?://[^/\s]*(?:service-now\.com|servicenow\.com|sharepoint\.com|okta\.com|code\.devsnc\.com)'

# Too long — session-specific
len(url) > 300

# NOTE: Search engine URLs (google.com/search, bing, duckduckgo) are NOT skipped
# — they get auto-formatted as "Engine: <decoded query>" (see above)
```
